# 离线字形装配契约（assembly v1）

## 目标与边界

新增一个纯 Python 数据处理入口，把多供稿的字形原料装配成可直接送入 v1 排版
（`pixel_type.service.process`）的交付文件。不接 UI、不接屏幕、不新增任何 CLI
子命令；原有 `pixel-type` 调用与全部既有子命令行为不变。

公共入口（均在 `pixel_type.assembly`）：

| 入口 | 用途 |
| --- | --- |
| `assemble(manifest: dict) -> dict` | 已解析清单字典 → 交付字典，纯内存 |
| `assemble_stream(stream) -> dict` | 从二进制流流式装配，大清单的低峰值 RSS 路径 |
| `assemble_file(source_path, output_path) -> dict` | 读清单 → 流式装配 → 原子新建交付文件 |
| `iter_cells(delivery, char)` | 遍历某字形全部有效格来源（透明格不产生） |
| `cell_source(delivery, char, x, y)` | 按字符 + 字形局部坐标查单格来源，透明/越界返回 `None` |
| `load_manifest(path)` | 严格读取 ≤32 MiB 清单（重复键、非有限数拒绝） |

任何结构、引用、放行或 v1 校验失败都抛 `AssemblyError`（`ValueError` 子类）。

## 输入清单

顶层恰好包含 `nodes`、`bindings`、`approved_suppliers`、`text`、`kerning`、
`line_width`、`line_height` 七个字段，整份清单 ≤32 MiB。

* ID 为 1–32 位 ASCII 字母、数字、下划线或连字符；节点 ID 全局唯一，供稿方
  ID 可重复；批准名单是无重复供稿方数组，允许为空。
* 节点 1–40000 个，其中原料节点（`kind:"fragment"`）至多 2048 个；每个节点
  独立声明 `width`、`height`（均 1–32），左上原点、坐标从零起。
* 原料节点字段为 `supplier` 与 `rows`；行数与每行宽度必须恰好等于声明尺寸。
  行内只允许三种字符：
  * `1` 带来源的亮点；
  * `0` 带来源的清除（供稿方确实抹掉了旧笔画）；
  * `.` 透明、没有来源，不作写入。
* 装配节点字段为 `layers`，1–4 层，从底到顶排列。每层 `{ref,src,dst}`：
  `ref` 引用任意节点（允许前向引用、多装配共用同一部件）；`src` 是引用节点内
  的非空半开窗 `[x0,y0,x1,y1]`，必须落在引用节点画布内；`dst` 是窗左上角在
  当前画布上的坐标，两维 −31..31。不缩放、不旋转；落在当前画布外的格舍弃。
* 画布起始全透明。合成时只有带来源的格（亮或清除）覆盖下层，透明格不覆盖。
  装配节点被再次引用时仍保留三态；来源始终追溯到**最后实际写入的原料节点及
  其原始坐标**，不会停在中间装配节点，也不会写成裁窗内相对坐标。
* 任一路径最多经过 64 个节点（含两端）。缺引用、源窗越界、环、超深均为输入
  错误；**未被本批文字用到的节点同样做结构与引用校验**。

## 绑定、文字与 v1 校验

`bindings` 中每条 `{char,node,advance,offset}` 与 `text` 中的每个**不同的非
换行字符**一一对应：不得多绑、重复或缺绑；绑定 1–256 条。字符、`advance`、
`offset`、`kerning`、`text`、`line_width`、`line_height` 与交付后的排版输入
一起走完整 v1 校验（含 200000 渲染像素预算）；没有隐式缺字回退，不改字偶、
不移动字形原点、不裁外沿留白。

## 放行判定（只针对交付字形）

逐格追溯交付字形中每个**最终有效格**（亮或带来源清除）。透明格不归任何来源。
若某有效格追溯到的原料供稿方不在 `approved_suppliers` 中，即使该格在 v1 位图
里看起来与透明相同（状态为清除 `0`），也拒绝整份交付。错误信息给出一个可稳定
定位的违规格：字符、字形局部坐标、状态、供稿方、原料节点 ID 与原料原始坐标。

以下情况**不**构成违规：未获批供稿被上层亮/清除盖住、被裁窗或位移裁掉、位于
从未被绑定到达的节点中。原料库里存在未获批供稿本身不导致整库被拒。

## 交付文件

单个带格式 JSON（`canonical_bytes`：`sort_keys`、两空格缩进、末尾换行），含：

* `layout_input`：可原样取出送给 v1 的排版输入。每个绑定使用节点整幅画布，
  亮点为 `1`，透明与清除都为 `0`；其余字段（`kerning`/`text`/行宽行高）按
  清单透传。
* `provenance`：
  * `encoding` 自述来源字位段，解读不依赖输入清单；
  * `fragments`：按原料节点 ID 排序的 `{id, supplier}` 表；
  * `glyphs`：每个字符一份 `{width,height,cells}`，`cells` 是标准 Base64
    （RFC 4648），按行主序（先 y 后 x）打包的 32 位小端来源字，**只包含有效
    格**，透明格不出现。

来源字位段：

| 位 | 含义 |
| --- | --- |
| 0–4 | 字形局部 x |
| 5–9 | 字形局部 y |
| 10 | 状态：1=亮点，0=带来源清除 |
| 11–15 | 原料节点内原始 x |
| 16–20 | 原料节点内原始 y |
| 21–31 | `provenance.fragments` 下标（11 位，0..2047） |

* `summary`：节点/原料/装配/绑定计数、批准名单、有效格/亮格/清除格数量。

调换 `nodes`、`bindings` 或批准名单的记录顺序不改变成功交付的字节（原料表按
ID 排序、字形按字符排序、来源按行主序）；层序仍有业务含义，不参与重排。

## 失败原子性与文件安全

坏输入、不能放行或写入失败时不留下半份交付，也不改动已有同名文件。交付通过
临时文件 + `os.link` 原子新建，目标路径（含符号链接）已存在则报错，绝不覆盖。

## 内存口径

大清单走 `pixel_type.json_stream.StreamingReader` 事件式解析：任意时刻只有
正在读取的单个节点以解析对象形式存在，整份 JSON 解析树从不同时驻留。三态合成
按绑定逐根进行，装配画布在该字形处理完后整体释放；原料三态画布只读且跨绑定
共享（最多 2048 × 1024 字节 ≈ 2 MiB）。不在磁盘建立任何求值索引或中间位图，
只允许正常交付文件与其发布所需临时文件。

## 压力样例与测量

`pixel_type.stress.build_stress_manifest()` 生成确定性极限样例：恰好 40000 个
32×32 节点、2048 个原料，全部节点从 64 个绑定可达；含跨分支共用部件、实际生效
的裁窗/负位移/出界舍弃、带来源清除与透明透底、一条恰好 64 节点的引用链；未获批
供稿只出现在被裁掉或盖住的位置。文字含非零字偶距与非零偏移。

测量入口（独立 Linux CPython 进程，标准库，不挂 CLI）：

```sh
python -I bench/stress_bench.py generate --output run/stress-manifest.json
python -I bench/stress_bench.py run --source run/stress-manifest.json \
    --delivery run/stress-delivery.json
```

`run` 在同一进程内完成流式结构断言、装配落盘、交付来源断言与 v1 排版，并用
`resource.getrusage(RUSAGE_SELF).ru_maxrss`（Linux 单位 KiB）报告峰值 RSS；
超过 128 MiB 以退出码 3 失败。断言覆盖：40000 节点全可达、最长路径 64、来源
全部获批、共享部件原料原始坐标不串位、出界/透明格无来源、清除格带状态 0、
v1 实际 placement/字偶距/墨迹。
